# AQUASEE 2.0 migration assessment

**Date:** 2026-11-07

## Repositories compared

- Current local site: `HeuoIP/aquaseenetwork`, `main`
- Directional redesign: `HeuoIP/aquasee-website`, `aquasee-2.0`
- 2.0 latest commit: `8e2e794` (`feat: strengthen Aquasee entity metadata for GEO`)

## Decision

Use the 2.0 branch as the **business and content direction**:

> AI-powered strategy, design and sourcing / delivery.

Keep the current local project as the **technical base for the migration** until
the 2.0 changes have been ported and checked. It currently contains the stronger
locale system, four published languages, inquiry safeguards, GEO structure and
runtime gates, llms endpoints, hreflang handling and the full measurement record.

## What 2.0 contributes

- Clear AI-powered positioning in `src/content/site.ts`.
- Service framing around AI-powered strategy, concept and experience design,
  and sourcing / delivery.
- AI usage sections attached to individual services.
- A simpler English-first information architecture and new Insights content.
- GEO-focused entity metadata improvements in the latest commits.

## What must not be lost during migration

- Chinese, Arabic and Russian content and RTL handling.
- Locale-aware routing and per-language hreflang rules.
- `/llms.txt` and `/llms-full.txt`.
- GEO structure and runtime release gates.
- Inquiry attribution, validation, fallback and unsubscribe handling.
- Cloudflare OpenNext deployment configuration.
- Existing disclosure rules for concept imagery and unfinished case studies.

## Recommended implementation order

1. Port the 2.0 positioning, service names and AI usage content into the current
   locale-aware content model.
2. Compare the 2.0 homepage and service layout against the current components;
   reuse visual changes only where they do not remove GEO and accessibility
   safeguards.
3. Add or adapt the 2.0 Insights articles, then generate localized summaries or
   mark languages unavailable rather than exposing incomplete alternates.
4. Run `npm run typecheck`, `npm run geo:check` and `npm run geo:runtime`.
5. Review the complete diff before creating a deployment commit.
